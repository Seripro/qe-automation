# ワーカー異常停止・再起動時の回復検証

- 実施日: 2026-11-22
- 状態: 再検証待ち
- 実行環境: `mdx-server`、直接実行ワーカー、SQLite待ち行列

## 目的

実行中のワーカーが異常停止したとき、中断されたジョブを明確に失敗とし、待機中ジョブを新しいワーカーが処理できることを確認する。

## 初回の統合テスト

`MgB2-worker-restart`を実行中、`Si-after-restart`を待機中としてワーカーを停止し、サービスを再起動した。

結果として両方のジョブが`FAILED`となり、`Si-after-restart`にも`Worker restarted while this job was running. Please submit it again.`が表示された。期待した「MgB₂だけ失敗、Siは待機を維持」とは異なる結果だった。

単一ワーカーならMgB₂の実行中にSiを取得できないため、この結果はテスト時に複数ワーカーが動作していた可能性を示す。テスト後の`pgrep -af 'app\\.worker|pw\\.x'`では、ワーカー1個・`pw.x`なしを確認した。

## 対応

- 起動時に進行中ジョブを`FAILED`へ遷移させる回復処理を実装した。
- 同じ実行データ領域に複数ワーカーが同時に起動できない排他ロックを追加した。
- 単体テストで、中断ジョブが失敗となること、待機ジョブが保持されること、2個目のワーカーがロックを取得できないことを確認した。

方針は[ADR-0007](../../decisions/0007-fail-interrupted-jobs-after-worker-restart.md)を参照する。

## 再検証手順

1. 通常設定でサービスを起動し、起動時に表示されたworker PIDを控える。
2. `MgB2-worker-restart`を実行中、`Si-after-restart`を待機中にする。
3. 控えたworker PIDだけを停止する。
4. サービスを再起動する。
5. MgB₂が中断失敗となり、Siが待機から実行・完了へ進むことを確認する。
