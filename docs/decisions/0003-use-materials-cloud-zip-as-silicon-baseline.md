# ADR-0003: Materials Cloud生成ZIPをシリコンの基準入力にする

- 日付: 2026-11-17
- 状態: 採用
- 決定者: 研究者（ユーザー）とAIアシスタント
- 関連資料: [シリコン入力一式の確認](../experiments/silicon/2026-11-17-input-inspection.md)、[QEバンド構造・PDOS計算チュートリアル](../tutorials/tutorial-qe-band.md)

## 背景・課題

シリコンの初回検証には、Materials Cloud QE input generatorで生成した `PWscf.zip` を取得した。入力パラメータを手作業で変更してから始めるか、生成結果を基準として最初の計算フローを再現するかを決める必要があった。

## 検討した選択肢

### 選択肢1: 最初から入力条件を手作業で変更する

- 半導体に対する占有方法などを個別に検討できる。
- 初学段階で、入力変更による影響と実行環境の問題を区別しにくくなる。

### 選択肢2: Materials Cloud生成ZIPをそのまま基準入力にする

- 教授から案内されたチュートリアル手順に従える。
- SCF、バンド、PDOSの標準フローを、入力変更の影響なしに確認できる。
- パラメータの妥当性の比較・最適化は後の課題になる。

## 判断

**選択肢2を採用する。**

`docs/experiments/silicon/input/PWscf.zip` をシリコンの基準入力とし、最初のSCF → バンド → PDOS計算では手作業で入力条件を変更しない。

## 理由

- 教授から案内されたMaterials Cloudを使う手順を、まず正確に再現するため。
- 既存の自動化スクリプトとGUIワークフローを検証するための基準ケースにするため。
- 物理的なパラメータ比較は、各設定の意味と計算結果を理解してから行うため。

## 影響・トレードオフ

- 現在のZIPに含まれる擬ポテンシャル、カットオフ、k点、smearing設定を初回計算の条件として記録する。
- 収束試験や占有方法の比較はMVPの初回動作確認後に行う。
- ZIP自体は変更せず、変更した計算を試す場合は別の入力・別の実験記録として扱う。

## 後で見直す条件

- 計算が収束しない、または後続計算が成立しない場合。
- 結果の比較・評価の目的上、収束試験や入力条件の変更が必要になった場合。
