# Naのバンド計算における対角化エラー

- 発生日: 2026-11-22
- 状態: 原因を限定（根本原因は未確定）
- 対象物質: Na
- 実行経路: Web UI → API → SQLite待ち行列 → 直接実行ワーカー
- QE: 7.6、OpenMP 4スレッド

## 現象

Naの入力ZIPをWeb UIから投入したところ、SCF計算は完了したが、Band段階で失敗した。

```text
BAND_RUNNING exited with status 1
```

`band.out` の末尾では、高対称k点経路の122点中104点目を計算中に次のエラーが出た。

```text
Error in routine cdiaghg (70):
S matrix not positive definite
```

## 確認できた事実

- SCF段階は成功している。
- SeeK-pathはNaを体心立方（`cI`）として認識し、`Γ → H → N → Γ → P → H → P → N` の経路を生成した。
- 自動化スクリプトは元の`pwscf.in`を`band.in`へ複製し、`calculation = 'bands'`、`nbnd = 18`、生成した高対称k点経路を設定している。
- エラーはWeb UIそのものではなく、生成済み`band.in`をQEの`pw.x`で実行したときに生じた。

## 現時点の解釈

このエラーは、QEが一般化固有値問題を解く際の数値的な対角化失敗である。構造不正、擬ポテンシャル、カットオフ、`nbnd`、高対称k点経路、対角化法、QEの版・実行環境などが関係し得るため、現時点で単一の原因とは断定しない。

Materials CloudまたはCOD由来のZIPを用いる全利用者に必ず起きるとは限らない。ZIPに含まれるSCF入力に対して、アプリがBand用の設定を自動生成するため、同一の`band.in`・QE版・擬ポテンシャル・実行環境であれば、GUIの有無にかかわらず再現する事象である。

## 追加切り分け（2026-11-24）

元のジョブを変更しない一時コピーで、失敗した`band.in`に対して一条件ずつ変更して実行した。実行環境はQE 7.6、OpenMP 4スレッドである。

| 条件 | 結果 | 判断 |
| --- | --- | --- |
| `nbnd = 18`、既定のDavidson法 | 104/122点目（P→N区間、`k=(0.225, 0.225, 0.275)`）で同じ`cdiaghg`エラー | 再現した。 |
| `nbnd = 18`、`diago_david_ndim = 2` | 同じ104点目で失敗 | Davidson部分空間の既定サイズだけでは説明できない。 |
| `nbnd = 18`、`diagonalization = 'cg'` | `JOB DONE.` | 同じ入力・k点経路でもCG法では完走する。 |
| `nbnd = 9`、既定のDavidson法 | `JOB DONE.` | k点経路・SCF再開データだけが原因ではない。 |

この結果から、失敗の直接の引き金は、Naのultrasoft擬ポテンシャルを用い、空状態を含む`nbnd = 18`を既定Davidson法で対角化する組合せにあると限定できる。`S matrix not positive definite`は、Davidson法が作る部分空間におけるUSPPの重なり行列を正定値として分解できなかったことを示す。構造・SCF収束・SeeK-pathが物理的に誤っていることを、このエラーだけから意味するものではない。

一方で、なぜこのNa擬ポテンシャル・40 Ry・18バンドで数値的に不安定になるか（カットオフ、擬ポテンシャル品質、QE 7.6または数値ライブラリの影響）は未確定である。`nbnd = 9`は空状態が不足し、バンド図の用途には十分でないため、回避策には採用しない。

## 次の切り分け（提案中）

1. `nbnd = 10`から`18`までを段階的に試し、Davidson法が失敗し始める境界を調べる。
2. `ecutwfc`・`ecutrho`を上げた場合と、別のNa擬ポテンシャルを使う場合を別実験として比較する。
3. QE 7.6のリンク先BLAS/LAPACKと、別QE版で再現するかを確認する。
4. 上記で物理的に妥当な設定が確認できてから、Na個別の回避策または利用者向けエラー表示を相談する。

この時点では、アプリが全物質に`cg`を自動適用する変更は行わない。`cg`はこのNa入力の有効な回避候補だが、既定Davidson法より遅く、全物質への自動適用は別途相談する。
