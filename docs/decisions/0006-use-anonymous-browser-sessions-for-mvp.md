# ADR-0006: MVPでは匿名ブラウザセッションでジョブを識別する

- 日付: 2026-11-21
- 状態: 採用
- 決定者: 研究者（ユーザー）とAIアシスタント
- 関連資料: [ADR-0005](0005-use-application-queue-on-mdx.md)、[ジョブ待ち行列・直接実行ワーカー仕様案](../job-queue-workflow-spec.md)

## 背景・課題

授業で最大90人程度が利用する可能性があるが、一般公開は想定しない。学生ごとの大学SSO連携は初期MVPには重く、ログインなしで完全に公開すると、他人のジョブ閲覧や過剰な投入を抑制できない。

サービスは学校Wi-Fiからのみアクセスできる想定である。ただし、このネットワーク制限はアプリケーションではなくネットワーク・公開設定に依存するため、公開前に実際に外部アクセスが遮断されていることを確認する。

## 検討した選択肢

### 選択肢1: 認証なし

- 実装は最小である。
- ジョブの所有者を区別できず、他人の結果閲覧・過剰投入を抑制できない。

### 選択肢2: 匿名ブラウザセッション

- 初回アクセス時にサーバーが推測困難な匿名IDを発行し、`HttpOnly` Cookieで保持する。
- ジョブを匿名IDへ紐付け、同じブラウザで自分の履歴を表示できる。
- Cookie削除・別ブラウザ・共有端末を厳密に区別できないため、強い本人認証ではない。

### 選択肢3: 大学SSOまたは学生個別アカウント

- 利用者ごとの上限・履歴・アクセス制御を強く管理できる。
- 外部認証連携、個人情報、運用の設計が必要になる。

## 判断

**選択肢2を採用する。**

MVPでは大学SSOを実装しない。サーバーが匿名ブラウザIDを発行して`HttpOnly`、`Secure`、`SameSite`属性を持つCookieに保存する。ジョブ詳細へのアクセスには、匿名ブラウザIDに加え、推測困難なジョブ閲覧トークンを使う。

localStorageには、画面復元用のジョブID一覧など、漏れてもジョブ閲覧権限にならない情報だけを保存する。Cookieや閲覧トークンそのものをlocalStorageへ保存しない。

## 影響・トレードオフ

- 同じブラウザでは、自分が投入したジョブの一覧と状態を表示できる。
- Cookie削除・別ブラウザ・シークレットモードでは同じ利用者と見なせず、厳密な利用者単位の制限はできない。
- ブラウザ単位の待機・実行中ジョブは初期値1件とし、加えてサービス全体の待ち行列上限・ZIP容量・実行時間を設定する。
- 結果URLや閲覧トークンを共有した人は結果を閲覧できるため、機密性の高い入力を扱わない。
- 学校Wi-Fi限定のネットワーク制限が実際に機能することは、公開前の運用確認項目とする。

## 後で見直す条件

- 授業で学生ごとの提出・履歴・公平な上限管理が必要になった場合。
- 学外アクセスや、より強い結果の秘匿性が必要になった場合。
- 大学SSOなど利用可能な認証基盤が明確になった場合。
