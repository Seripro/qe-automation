# 進捗報告メモ（2026-11-24）

## 今回できたこと

- Quantum ESPRESSOの検証済み`PWscf.zip`をブラウザから登録し、mdx-serverで直接実行するWebアプリを実装した。
- SQLite待ち行列と単一ワーカーにより、SCF → バンド構造 → NSCF/PDOSを順次実行できる。
- SiとMgB₂で、ブラウザからの投入、進捗・ログ確認、バンド図・PDOS図の表示まで成功した。
- 不正ZIPの拒否、実行中キャンセル、段階ごとのタイムアウト、通常再起動後の履歴復元を確認した。
- ワーカー異常停止時は、中断ジョブを失敗として再投入を促し、待機中ジョブを継続する方針を実装・検証した。

## 現在のMVP範囲

- 入力は、少なくとも`PWscf/pwscf.in`を含む検証済みZIPに限定する。
- ユーザーは物質名ラベルとZIPを登録するだけで、QEの詳細パラメータは画面から変更しない。
- 実行先はmdx-serverで、アプリ側待ち行列の同時実行数は1件である。
- 個別ログインは使わず、匿名ブラウザCookieで自分のジョブを区別する。

## 実装中に生じた問題と対応

| 問題 | 原因・状況 | 対応と得られた知見 |
| --- | --- | --- |
| Band計算が開始できない | Webワーカーが、SeeK-path用の`numpy`・`seekpath`を持たないPython環境でスクリプトを起動していた。 | QE用仮想環境を子プロセスの`PATH`へ明示的に設定した。Webアプリの仮想環境と、計算補助ツールの実行環境を分けて管理する必要がある。 |
| バンド図に不要な縦線が出た | 高対称k点経路の不連続点を一本の線として描画していた。 | 不連続点で曲線を分割するよう描画処理を修正した。計算値だけでなく可視化の正しさも確認が必要だと分かった。 |
| NaでBand計算が停止した | SCFは成功したが、Band段階でQEの`S matrix not positive definite`エラーが発生した。 | GUIの問題ではなく、アプリが生成する`band.in`を含むQE計算条件の問題として記録した。対角化法、`nbnd`、カットオフ、k点経路を今後切り分ける。 |
| キャンセル検証時に別ジョブのログが残った | 新しいジョブを選択・投入しても、フロントエンドのログ表示状態を初期化していなかった。 | ジョブ切替・新規投入時に古いログとメッセージを消すよう修正した。 |
| ワーカー停止後に待機ジョブも失敗した | 複数ワーカーが動作していた可能性があり、待機中のSiジョブも実行状態になっていた。 | 実行データ領域ごとの排他ロックを追加した。再検証では、中断したMgB₂だけが失敗し、待機していたSiは再起動後に完了した。 |

これらの問題は、計算処理・実行環境・画面表示・待ち行列運用を分けて観察し、原因を切り分けながら修正した。

## 課題

- NaではSCF成功後のBand計算で、QEの`S matrix not positive definite`エラーが発生した。GUI固有ではなく、アプリが生成するBand用入力を含む計算条件の切り分けが必要である。
- カットオフ、k点メッシュ、`nbnd`などの収束性と、計算結果の物理的妥当性は未評価である。
- 学校Wi-Fi限定アクセス、利用者ごとの上限、アップロード上限、運用時のプロセス管理は公開前に決める必要がある。

Naの`pwscf.in`と自動生成した`band.in`を比較し、対角化法、`nbnd`、カットオフ、k点経路を一つずつ検証する。
