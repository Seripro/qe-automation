# GUIワークフロー仕様案: 検証済み入力によるQEバンド・PDOS計算

- 状態: **提案中**
- 作成日: 2026-11-17
- 根拠: [QEバンド構造・PDOS計算チュートリアル](tutorials/tutorial-qe-band.md)
- 関連する既存案: [`../webapp/REQUIREMENTS.md`](../webapp/REQUIREMENTS.md)

## 1. 目的

研究室チュートリアルで手作業として行う、入力一式の配置、SCF計算、バンド計算、PDOS計算、結果確認を、一つのWebジョブとして安全かつ追跡可能に実行する。

このMVPは、QE入力ファイルをゼロから作成するGUIではない。まずは**検証済みの `PWscf.zip` を入力**とし、ジョブ管理・処理の可視化・結果理解の支援を評価対象にする。

## 2. 対象ユーザーと前提

- 対象: QEチュートリアルを実施する学生・研究室内の利用者
- アクセス: 学内VPN経由を想定
- 実行先: 大学のPBS計算サーバー
- 入力: 少なくとも `pwscf.in` を含む、計算済み・確認済みのZIPファイル
- 実行環境: QE、PBS、SeeK-path、プロット環境がサーバー側に設定済みであること

ここでいう「検証済み」は、少なくとも対象環境で `pwscf.in` の構文、擬ポテンシャルの参照先、格子・原子種の設定を確認済みであることを指す。計算結果の物理的妥当性をGUIが自動保証する意味ではない。

## 3. MVPの利用フロー

```text
1. 利用者が物質名ラベルとPWscf.zipを登録する
        ↓
2. アプリがZIPを検証し、専用作業ディレクトリへ安全に展開する
        ↓
3. SCF計算をPBSへ投入し、状態・ログ・収束情報を表示する
        ↓
4. band.inと高対称k点パスを生成し、バンド計算を実行する
        ↓
5. フェルミ準位を用いてバンド図を生成・表示する
        ↓
6. NSCF・PDOS計算を実行し、全DOS・PDOS図を生成・表示する
        ↓
7. 入力、ログ、生成データ、図を閲覧・ダウンロードする
```

失敗時は次段階を実行せず、失敗した段階、PBSの状態、関連ログを表示する。

## 4. 画面と機能

### 4.1 ジョブ投入画面

| 項目 | MVPでの扱い |
|---|---|
| 物質名ラベル | 必須。表示・履歴用。英数字、`_`、`-` に制限する。 |
| `PWscf.zip` | 必須。アップロードする。 |
| 入力の検証結果 | `pwscf.in` の有無、ZIPサイズ、展開できるかを表示する。 |
| 実行ボタン | 検証成功後にジョブを作成する。 |
| 詳細設定 | MVPでは表示しない。入力ZIPの設定を使用する。 |

### 4.2 ジョブ詳細画面

処理の段階、現在の状態、開始時刻、更新時刻、PBSジョブIDを表示する。

| 段階 | 処理 | 成功時に確認する主な出力 |
|---|---|---|
| `VALIDATING` | ZIP・入力内容の検証 | `pwscf.in` |
| `SCF_QUEUED` / `SCF_RUNNING` | SCF計算 | `scf.out`、収束・`JOB DONE` |
| `BAND_PREPARING` | `band.in` とk点パスの生成 | `band.in`、`kp.pwscf` |
| `BAND_QUEUED` / `BAND_RUNNING` | `pw.x` と `bands.x` | `bands.out.gnu` |
| `PDOS_PREPARING` | `nscf.in`、`pdos.in` の生成 | 入力ファイル |
| `PDOS_QUEUED` / `PDOS_RUNNING` | `pw.x` と `projwfc.x` | `pdos.out`、PDOSデータ |
| `COMPLETED` | 図・結果を公開 | `bands.png`、`pdos.png` |
| `FAILED` / `CANCELLED` | 以後の処理を停止 | エラー理由・ログ |

進捗更新はWebSocketで通知し、再接続時にはREST APIから現在状態を取得できるようにする。

### 4.3 結果画面

- バンド図をフェルミ準位を0 eVとして表示する。
- PDOS図では全DOSと、集計できた元素・軌道別系列を表示する。
- 各図、入力ファイル、標準出力ログ、生成データを個別にダウンロードできるようにする。
- 「計算は正常終了したが物理的な妥当性は別途確認が必要」と表示する。

## 5. 自動化する処理と保持する情報

| チュートリアルの手作業 | MVPでの扱い | 利用者に見せる情報 |
|---|---|---|
| ZIPをサーバーへ転送・展開 | 自動化 | 入力名、検証結果 |
| `scf.sh` の作成と `qsub` | 自動化 | PBS ID、ログ、状態 |
| Kohn–Sham状態数の抽出 | 自動化 | 抽出値、`nbnd` の決定方法 |
| XCrySDenでのk点パス作成 | SeeK-pathによる自動生成を採用候補 | 使用した経路と生成済み `kp.pwscf` |
| `band.sh` の作成と投入 | 自動化 | バンド計算ログ、状態 |
| gnuplotでバンド図を作成 | 自動化 | フェルミ準位、バンド図 |
| `nscf` / `projwfc.x` | 自動化 | PDOS計算ログ、状態 |
| `sumpdos.x` とPDOS描画 | 自動化 | 対象元素・軌道、PDOS図 |
| FermiSurfer | 範囲外 | 将来拡張候補 |

## 6. MVPに含める範囲（提案）

### 含める

- 検証済み `PWscf.zip` のアップロード
- ZIP検証、安全な展開、ジョブごとの独立作業ディレクトリ
- SCF → バンド → NSCF/PDOS の逐次実行
- SeeK-pathによる自動k点パス生成
- PBSジョブの状態、段階、ログの表示
- バンド図・PDOS図、入力・ログ・図のダウンロード
- ジョブ履歴と失敗理由の表示

PDOSはMVPの必須段階とする。詳細は [ADR-0001](decisions/0001-include-pdos-in-mvp.md) を参照する。

### 含めない

- CIFからの完全な `pwscf.in` 自動生成
- 擬ポテンシャル、`ecutwfc`、k点メッシュなどを編集するフォーム
- XCrySDenをブラウザから操作する機能
- 手動k点パス編集
- フェルミ面の可視化
- 複数計算の比較、ユーザー認証、共同利用の細かな権限管理

これらを除外する理由は、QE入力の妥当性をユーザーにどう支援するかという別の設計・物理課題を、最初のジョブ管理・可視化の検証と分離するためである。

## 7. 安全性・運用上の必須条件

- 物質名ラベルをシェル文字列として連結しない。許可文字を検証し、外部コマンドは引数配列で起動する。
- ZIPに含まれるパスを検査し、作業ディレクトリ外への展開（パストラバーサル）を防ぐ。
- ジョブIDから作る専用作業ディレクトリにのみファイルを配置する。
- アップロード上限、同時実行数、実行時間上限を設定する。
- `JOB DONE` の有無だけで待ち続けない。PBS終了状態、エラー出力、タイムアウトを確認して失敗を確定する。
- Webサーバー再起動後にも追跡できるよう、ジョブ状態とPBSジョブIDを永続化する。

## 8. MVPの評価案（未確定）

CLIチュートリアルとGUIを比較し、以下を候補として評価する。

- 計算投入から図の確認までに必要な操作数・時間
- ファイル名や実行順序に関する操作ミスの数
- 失敗時に原因へ到達するまでの時間
- SCF、バンド、PDOSの役割を利用者が説明できるか

被験者数、対象者、評価手順、倫理面の扱いは指導教員と相談して決定する。

## 9. 決める必要がある事項

1. SeeK-pathの自動k点パスだけで始めるか、初期版から手動入力も許可するか。
2. WebサーバーとPBS投入ホストの配置・権限をどうするか。
3. 評価対象を「研究室内の経験者」にするか、「QE初学者」にするか。

最初の検証対象はシリコンとする。詳細は [ADR-0002](decisions/0002-use-silicon-as-first-validation-material.md) を参照する。
