# ADR-0001: MVPにPDOS計算・表示を含める

- 日付: 2026-11-17
- 状態: 採用
- 決定者: 研究者（ユーザー）とAIアシスタント
- 関連資料: [GUIワークフロー仕様案](../gui-workflow-spec.md)、[QEバンド構造・PDOS計算チュートリアル](../tutorials/tutorial-qe-band.md)

## 背景・課題

研究室チュートリアルと既存の `qe_auto_kp.sh` は、SCF計算、バンド構造計算、PDOS計算までを連続して実行する。MVPの完成条件をバンド図までに限定するか、PDOSの生成・表示まで含めるかを決める必要があった。

## 検討した選択肢

### 選択肢1: SCFとバンド構造までをMVPにする

- 実装する計算段階が少なく、最初の動作確認を早く行える。
- 原子・軌道ごとの状態の寄与を表示できない。
- チュートリアルの一連の処理を最後までGUI化したことにならない。

### 選択肢2: SCF、バンド構造、PDOSまでをMVPにする

- チュートリアルの主な処理を一つのワークフローとして扱える。
- バンド図に加えて、元素・軌道の寄与をPDOSとして可視化できる。
- NSCF、`projwfc.x`、`sumpdos.x`、PDOS描画の失敗処理と結果表示が追加で必要になる。

## 判断

**選択肢2を採用する。**

MVPは、検証済み `PWscf.zip` を入力として、SCF → バンド構造 → NSCF/PDOS計算を順に実行し、バンド図とPDOS図を表示する範囲とする。

## 理由

- 既存の自動化スクリプトがPDOSまでを対象としており、実装の基礎がある。
- 研究室チュートリアルの計算フローと対応する。
- バンド構造だけよりも、計算結果の理解を支援するGUIとしての価値を示しやすい。

## 影響・トレードオフ

- 実装・検証対象にPDOS用の後続計算、軌道別ファイルの集計、グラフ表示が追加される。
- PDOS段階のみが失敗した場合にも、SCF・バンド結果は閲覧可能な状態を扱う必要がある。
- 最初の実装は、対象物質で実際に生成されるPDOSファイル名の形式を確認してから進める。

## 後で見直す条件

- PDOS処理が計算サーバーの制約で安定して実行できない場合。
- MVPの期限に対して、PDOS表示までの実装・検証コストが過大と判断された場合。
